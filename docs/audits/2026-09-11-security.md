## HIGH

### H-1 — Accept-any-certificate (no pinning, no trust-on-first-use) for allowed hosts

**Files:** `Packages/SonosKit/Sources/SonosKit/Transport/URLSessionTransport.swift:57-69`; `Packages/SonosKit/Sources/SonosKit/Transport/TrustPolicy.swift:20-33`

**What the code does** *(verified)*. `TrustDelegate.urlSession(_:didReceive:completionHandler:)` checks `store.shouldTrust(host: space.host)` and, if true, calls `completionHandler(.useCredential, URLCredential(trust: trust))` at line 68. `URLCredential(trust:)` accepts the presented `SecTrust` **without evaluating it and without comparing it to anything previously seen**. `TrustStore.shouldTrust` (TrustPolicy.swift:30-32) is only `isPrivateIPv4(host) && hosts.contains(host)` — a membership test on a bare IP string. No certificate, public key, fingerprint, or subject is ever recorded or compared. There is no TOFU: the first certificate is not pinned, so the second, third, and every subsequent certificate is equally accepted.

**Attack.** Preconditions: attacker on the LAN, plus the ability to occupy or redirect a speaker's IPv4 address (ARP spoofing, a DHCP lease race after a speaker reboots, a hostile device statically assigned to a freed address, or simply a rogue device that wins the mDNS announcement — see H-2). Once the app has called `allow(host:)` for that IP, the attacker terminates TLS with a self-signed certificate of their choosing and the app accepts it silently.

**Impact.** Full MITM of the REST and websocket channel for that host: the attacker sees every command the user issues and, more importantly, **controls every response and every pushed event**. That attacker-controlled JSON is the input to H-3, H-4, M-1, M-3, and M-4 below — this finding is the gateway that makes the parsing findings reachable in the strong sense. It does not expose a credential (the API key is public, see I-1) and does not yield code execution. Certificate change produces no warning, no log line, and no user-visible signal.

**Fix.** Implement real TOFU. On the first successful handshake with a host, extract the leaf certificate's SPKI hash (`SecCertificateCopyKey` → `SecKeyCopyExternalRepresentation` → SHA-256) and store it alongside the host in `TrustStore`. On every later handshake for that host, require the SPKI hash to match; on mismatch, decline the challenge and surface a distinct `HouseholdStatus` (e.g. `.certificateChanged`) so the UI can tell the user a speaker's identity changed. Persist the map across launches (the app container is sandboxed; `Application Support` or the keychain are both fine) so the pinning survives a restart — today `URLSessionTransport.init` builds a fresh empty `TrustStore` every launch and again on every `AppState.retryDiscovery()` (`SonosRemote/App/AppState.swift:62, 86`). Bind the entry to the Sonos player UUID that the certificate was first seen for, so a changed cert on a *re-used* IP is distinguishable from a changed cert on the *same* player.

### H-2 — Bonjour TXT `location` host is used unvalidated; a rogue mDNS responder can point the app at an arbitrary internet host

**Files:** `Packages/SonosKit/Sources/SonosKit/Discovery/BonjourDiscovery.swift:26-31`; `Packages/SonosKit/Sources/SonosKit/Household/Household.swift:163-182`

**What the code does** *(verified)*. `BonjourDiscovery.player(fromTXT:)` takes `txt["location"]`, parses it with `URLComponents(string:)`, and keeps **only `.host`**:

```
guard let id = txt["uuid"], !id.isEmpty,
      let location = txt["location"],
      let host = URLComponents(string: location)?.host, !host.isEmpty else { return nil }
return DiscoveredPlayer(id: id, address: host, householdID: txt["hhid"])
```

The only validation is "parses as a URL" and "host is non-empty". There is **no scheme allowlist, no check that the host is an IP literal rather than a DNS name, and no check that it falls in a private range.** `Household.handle(discovery:)` then stores it (`addresses[player.id] = player.address`, line 168) and uses it as the gateway for the topology fetch (line 175/180 → `startBootstrap()` → `refreshTopology()` → `api.groups(from: gateway)`).

The existing test at `Packages/SonosKit/Tests/SonosKitTests/DiscoveryTests.swift:21` only asserts that the literal string `"not a url"` is rejected — a well-formed URL naming a public host passes cleanly.

**Attack.** Preconditions: attacker on the LAN able to send mDNS responses (no privileged position needed; mDNS is multicast and unauthenticated), plus control of a domain with a publicly-trusted certificate. The attacker advertises `_sonos._tcp` with `uuid=RINCON_…` and `location=http://speakers.attacker.example/xml/device_description.xml`. The app derives `address = "speakers.attacker.example"` and issues `GET https://speakers.attacker.example:1443/api/v1/households/local/groups` with the API key header.

Note the two-path split. For that host `TrustStore.shouldTrust` returns **false** (`isPrivateIPv4` fails on a DNS name — correctly, and this is asserted at `TrustPolicyTests.swift:12`), so the delegate falls through to `.performDefaultHandling` at `URLSessionTransport.swift:65`. The connection therefore succeeds only if the attacker presents a **publicly valid** certificate for that name on port 1443 — routine to obtain. This is not blocked by ATS: the request is `https`, and `NSAllowsLocalNetworking` is irrelevant to it.

**Impact.** Three distinct consequences:
1. **Egress from a "local network only" app.** A tool whose entire privacy story is "it never leaves your LAN" is made to open an outbound TLS connection to an attacker-chosen internet host, on a trigger the user never sees. That is a beacon: it discloses the user's public IP, that they run this app, and their activity timing.
2. **The attacker's server becomes the household.** Its JSON populates `snapshot.players`, `snapshot.groups`, and `snapshot.favorites` — all rendered in the UI.
3. **Trust-store pivot.** `refreshTopology` (Household.swift:289, 294) and the `.groups` socket handler (Household.swift:399, 404) call `trustStore?.allow(host:)` for every address in that payload. See M-1 — the attacker's response silently widens H-1's accept-any-cert to any private IPv4 address they name.

**Fix.** Validate before the address is ever stored. In `player(fromTXT:)`: require the scheme to be exactly `http` or `https`; require the host to parse as an IPv4 or IPv6 *literal* (reject DNS names outright — Sonos always publishes a literal, as `knowledge/domain/sonos-local-api.md:3` documents); and require it to be in a private / link-local range (RFC 1918, `169.254/16`, `fc00::/7`, `fe80::/10`). Return `nil` otherwise. Apply the same predicate to `WirePlayer.host(fromWebsocketURL:)` (`Wire/WireTypes.swift:30-32`) so a topology payload cannot reintroduce a public host, and make `Household` drop players whose address fails it rather than silently storing `""` (`Wire/WireMapping.swift:11` currently coerces a failed parse to an empty string). Lift the range test out of `TrustPolicy.isPrivateIPv4` into a shared `isLocalSpeakerAddress` used by both discovery and trust, so the two can never disagree.

### H-3 — Remote crash: `preconditionFailure` on a network-derived address

**Files:** `Packages/SonosKit/Sources/SonosKit/LocalAPI/LocalAPIClient.swift:87-89`; `Packages/SonosKit/Sources/SonosKit/Socket/PlayerSocket.swift:31-33`; `Packages/SonosKit/Sources/SonosKit/UPnP/UPnPClient.swift:89-91`

**What the code does** *(verified)*. All three sites build a URL by string interpolation and hard-abort if it fails to parse:

```
guard let url = URL(string: "https://\(address):\(Self.port)/api/v1\(path)") else {
    preconditionFailure("Bad local API URL for \(address) \(path)")
}
```

`preconditionFailure` traps in **both** Debug and Release — `project.yml` sets no `-Ounchecked` (grep confirmed no `Ounchecked|SWIFT_OPTIMIZATION` override anywhere), and `precondition` is only elided under `-Ounchecked`, never under plain `-O`. So this is a hard, unrecoverable process abort in shipped builds.

`address` is entirely attacker-controlled: from the Bonjour TXT record (H-2) or from `websocketUrl` in a topology payload (H-1). `path` likewise embeds server-supplied `groupID` / `playerID` / `favoriteID` strings (see M-2).

**Attack.** Preconditions: LAN access and the ability to send an mDNS response — that alone is sufficient, no MITM required. The attacker advertises a TXT record whose `location` yields a host string that `URLComponents` accepts but that is invalid when re-interpolated into `https://<host>:1443/...`. The clearest class is an IPv6 literal: `URLComponents(string:)` parses `http://[fe80::1]:1400/x` happily, and the bracket handling of `.host` differs across Foundation versions *(inferred — the exact bracket behaviour on this OS was not exercised)*; an unbracketed `fe80::1` interpolated into `https://fe80::1:1443/...` does not parse as a URL. Hosts containing characters legal in a URL component but illegal in this position fall in the same class. The attacker does not need to be right on the first try — mDNS lets them iterate freely.

**Impact.** Unauthenticated remote denial of service: the menu-bar app terminates. Because `SMAppService` launch-at-login is offered (`SonosRemote/Views/Settings/SettingsScreen.swift:81`) and the malicious record persists, the app crashes again on each relaunch — a persistent, self-reinforcing DoS. The abort message is written to the crash report along with the attacker-supplied address.

**Fix.** Never trap on network data. Change `makeRequest` to return `APIRequest?` (or `throws`), have `perform` throw a new `LocalAPIError.badAddress`, and let the existing `catch` in `Household.refreshTopology` (line 307) absorb it. For `PlayerSocket.init`, make the initialiser failable and have `Household.ensureSockets` (line 349) skip players whose URL cannot be built. Build URLs with `URLComponents` (setting `host`/`port`/`path` as components) rather than interpolating into a format string, so bracketing and escaping are handled by Foundation. Combine with the H-2 address allowlist, which removes most of this input space up front.

### H-4 — Remote crash: integer overflow trap in progress-bar arithmetic

**Files:** `SonosRemote/App/PlaybackDisplay.swift:8-13` and `:22-26`; reached from `SonosRemote/Views/Main/ProgressBarView.swift:12, 34`

**What the code does** *(verified)*. Two unchecked `Int` operations on values that come straight off the wire:

```
// PlaybackDisplay.swift:11
if elapsed > 0 { position += Int(elapsed * 1000) }

// PlaybackDisplay.swift:23-24
let remainingMillis = max(0, duration - position)
let totalSeconds = (remainingMillis + 999) / 1000
```

`position` originates as `WirePlaybackStatus.positionMillis` (`Wire/WireTypes.swift:53`, an `Int`) and `duration` as `WireTrack.durationMillis` (`Wire/WireTypes.swift:72`, an `Int`). Both flow unclamped through `WireMapping.swift:48`, `SocketFrame.swift:91/98`, `SnapshotReducer.swift:32-44` into `PlaybackProgress`. Swift's `+=` and `+` on `Int` trap on overflow under the default `-O`; `-Ounchecked` is not set *(verified by grep)*.

**Attack.** Preconditions: LAN access plus the ability to feed the app event JSON — i.e. a rogue speaker the app has adopted (H-2) or a MITM'd real one (H-1). `JSONDecoder` decodes `9223372036854775807` into `Int` successfully *(inferred — standard `Codable` behaviour for values within `Int64`)*, so the attacker sends a `metadataStatus` frame with `durationMillis: 9223372036854775807`. Any subsequent render of the progress bar computes `remainingMillis + 999`, which overflows and traps. The `position += Int(elapsed * 1000)` path at line 11 traps symmetrically on a near-`Int.max` `positionMillis`. Both are single-frame, no timing required.

`ProgressBarView` renders whenever the selected group has a position and a duration (`ProgressBarView.swift:14-16`), so the crash fires as soon as the user opens the panel on the affected room — and `state.tick` re-renders it once a second while playing (`AppState.swift:140-154`), so it will fire again immediately on relaunch.

**Impact.** Unauthenticated remote denial of service, same persistence characteristics as H-3. No memory-safety consequence — Swift's trap is the *safe* outcome — but the app is unusable while the malicious speaker is present.

**Fix.** Clamp at the trust boundary, which is the right layer: in `PlaybackProgress.init(wire:reportedAt:)` (`Wire/WireMapping.swift:46-56`) and in the `durationMillis` path at `SocketFrame.swift:98`, reject or clamp to a sane ceiling (24 h in milliseconds, `86_400_000`, is generous for any track) and treat anything outside as "unknown". Belt and braces, switch the two arithmetic sites to overflow-safe forms — `position = position.addingReportingOverflow(delta).partialValue` guarded, or simply do the arithmetic in `Int64`/`Double` with an explicit bound. Add a regression test alongside the existing `SonosRemoteTests/PlaybackDisplayTests.swift` that feeds `Int.max` and asserts no trap.

## MEDIUM

### M-1 — Trust store is widened by attacker-controlled topology payloads

**Files:** `Packages/SonosKit/Sources/SonosKit/Household/Household.swift:430-439` (`allowTrust(forWirePlayers:)`), called at `:289` and `:399`; plus the direct loops at `:292-295` and `:402-405`

**What the code does** *(verified)*. Every host named in a topology response — REST or the `.groups` websocket push — is added to the trust store, before the `removedPlayers` filter and without any liveness or identity check. The comment at line 430 states this is deliberate.

**Attack.** Preconditions: one adopted rogue speaker (H-2) or one MITM'd connection (H-1). The attacker returns a topology listing `websocketUrl` values for arbitrary private IPv4 addresses on the user's LAN. Each is passed to `trustStore?.allow(host:)`. Since `shouldTrust` is `isPrivateIPv4 && contains`, the attacker has now made the app accept **any** certificate for those addresses.

**Impact.** Blast-radius amplification of H-1 from "hosts the app genuinely discovered" to "any private IPv4 the attacker names". The practical ceiling is bounded — this `URLSession` is only ever used for Sonos REST/websocket/UPnP calls, so the attacker gains no access to unrelated services — but it removes the "we only trust what Bonjour showed us" property the design is reaching for.

**Fix.** Only `allow(host:)` an address that discovery has independently reported for a player id that is currently present (i.e. gate on `addresses[player.id]` matching, or on the id being in the discovery-confirmed set). Combine with H-1's SPKI pinning, after which "allowed" no longer means "any certificate". Prune entries in `.lost` handling (see L-2).

### M-2 — Server-supplied identifiers interpolated unescaped into REST paths

**File:** `Packages/SonosKit/Sources/SonosKit/LocalAPI/LocalAPIClient.swift:28-71` (13 call sites), assembled at `:87`

**What the code does** *(verified)*. Group, player, and favorite ids are interpolated straight into path strings — `"/groups/\(groupID)/playback/play"`, `"/players/\(playerID)/playerVolume"` — and then into `URL(string: "https://\(address):\(Self.port)/api/v1\(path)")`. There is no percent-encoding and no character allowlist. Those ids come from the speakers' JSON (`WireGroup.id`, `WirePlayer.id`, `WireFavorite.id` in `Wire/WireTypes.swift`) and are carried through the reducer into the UI untouched.

**Attack.** Preconditions: a rogue or MITM'd speaker (H-1/H-2) that is a member of the household, so its ids appear in the *legitimate* topology. It publishes a group whose `id` contains path-control characters (`../` segments, `?`, `#`). When the user presses Play on that room, the app sends a request whose effective path or query differs from the intended one — to whichever coordinator address the group names, which may be a **genuine** speaker.

**Impact.** Limited request forgery against the local Control API: the attacker can steer a user-initiated action to a different endpoint on a real speaker, or truncate the path with `#`. The API surface is speaker control, so the worst outcome is unintended speaker state, not data disclosure. Rated Medium for the combination of "attacker-chosen request path" and "sent to a trusted device".

**Fix.** Percent-encode each interpolated id with `addingPercentEncoding(withAllowedCharacters: .urlPathAllowed)` minus `/`, or build the URL via `URLComponents` and assign `path` as an array-joined component list so Foundation escapes it. Additionally, validate ids against the documented shape at decode time (Sonos ids are `RINCON_…` / opaque alphanumerics) and drop entities whose ids contain `/`, `?`, `#`, or control characters.

### M-3 — Artwork URLs are unrestricted in scheme and host

**Files:** `Packages/SonosKit/Sources/SonosKit/Wire/WireMapping.swift:24` and `:37`; rendered at `SonosRemote/Views/Artwork.swift:10`, used from `HeroView.swift:15`, `FavoriteRow.swift:12`, `RoomRowView.swift:18`, `GroupScreen.swift:16`, `HeaderView.swift:22`

**What the code does** *(verified)*. `artworkURL: track?.imageUrl.flatMap(URL.init(string:))` and `imageURL: wire.imageUrl.flatMap(URL.init(string:))` — any string that parses as a URL is accepted, with no scheme allowlist, no host restriction, and no size limit. `Artwork` hands it to `AsyncImage(url:)`, which fetches via the shared `URLSession` *(inferred — `AsyncImage` is documented to use `URLSession.shared`; not exercised here)*, a session entirely separate from the `TrustDelegate`-guarded one in `URLSessionTransport`.

**Attack.** Preconditions: a rogue or MITM'd speaker supplying track metadata or favorites. It sets `imageUrl` to an attacker-controlled `https://` URL. The app fetches it automatically on render, with no user action beyond opening the panel.

**Impact.** (a) **Tracking beacon / egress** — the same "never leaves your LAN" violation as H-2, but on a channel that fires on every artwork render and carries a unique URL per victim, giving the attacker presence, public IP, and per-open timing. (b) **Limited SSRF** — a `http://<internal-host>/...` URL causes a GET from inside the user's network; ATS would normally block cleartext, but `NSAllowsLocalNetworking` (`Info.plist:29-33`) relaxes exactly that for local destinations *(inferred — ATS local-networking semantics were not exercised)*. The app cannot read the response body (it is decoded as an image or discarded), so this is blind-SSRF-shaped: useful for reachability probing and for triggering side effects on GET endpoints, not for exfiltration. (c) **Unbounded download** — no size cap; a multi-gigabyte body is buffered by the image loader. `file://` URLs are also accepted by `URL(string:)` here; the shared session can load them, though the result is only ever decoded as an image, so this is a nuisance rather than a disclosure.

**Fix.** Filter at the mapping layer, not the view: accept a URL only if its scheme is `https` — or `http` *and* its host is a private/link-local literal, which is what real Sonos artwork uses. Reject `file:`, `data:`, `ftp:`, and everything else. Ideally route artwork through the same `Transport` used for the API so it inherits the trust policy and timeout, and set an explicit byte ceiling on the response.

### M-4 — Markdown/link injection into UI text from attacker-controlled track metadata

**File:** `SonosRemote/Views/Group/GroupScreen.swift:62`; lower-impact variants at `VolumeSliderView.swift:37`, `FavoriteRow.swift:28`, `RoomRowView.swift:35`, `SoundScreen.swift:29, 64`, `ToneSlider.swift:18`

**What the code does** *(verified)*. `Text("Playing \(now.title), will switch to this group")` is a **string literal with interpolation**, which Swift resolves to the `LocalizedStringKey` overload of `Text.init` — and SwiftUI renders `LocalizedStringKey` content as Markdown *(inferred — documented SwiftUI behaviour; not exercised here)*. `now.title` comes straight from `WireTrack.name` / `WireContainer.name`.

This is a genuinely subtle distinction, and the codebase gets it right almost everywhere: `Text(now.title)` (`HeroView.swift:26`), `Text(favorite.name)` (`FavoriteRow.swift:14`), and `Text(player.name)` (`GroupScreen.swift:58`) pass a `String` *variable*, which binds to the non-localized `StringProtocol` overload and is rendered verbatim. Line 62 is the one place an untrusted value lands inside a literal. The accessibility-label sites listed above have the same shape but are only read by assistive technology.

**Attack.** Preconditions: a rogue or MITM'd speaker. It sets the track name to Markdown containing a link, e.g. a bracketed label pointing at an attacker URL. The Group screen renders it as a live, clickable link inside a trusted-looking native app; clicking opens the attacker's URL in the user's browser.

**Impact.** Phishing / unexpected navigation from content the user reasonably believes is their own music library. No code execution. Rated Medium because it converts passive attacker-controlled text into an active UI affordance.

**Fix.** Change line 62 to compose with a variable rather than a literal — e.g. `Text(verbatim: "Playing \(now.title), will switch to this group")`, or split into `Text("Playing ") + Text(now.title) + Text(", will switch to this group")` where the middle term takes the `String` overload. Apply the same to the accessibility labels. As a general rule for this codebase: never interpolate wire data into a `Text("…")` or `.accessibilityLabel("…")` string literal.

### M-5 — Unbounded growth from a hostile mDNS responder or topology payload

**Files:** `Packages/SonosKit/Sources/SonosKit/Household/Household.swift:34, 163-182, 344-360`; `Packages/SonosKit/Sources/SonosKit/Wire/WireTypes.swift:11-14`

**What the code does** *(verified)*. There is no cap anywhere on the number of players. `addresses` (line 34) grows per discovered id; `ensureSockets` (line 349) opens one `PlayerSocket` per player in the snapshot, each with its own reconnect loop and 30-second pinger; `TrustStore.hosts` grows monotonically; `GroupsResponse.groups`/`players` decode arrays of unbounded length; the wire strings (`name`, `id`, `imageUrl`) have no length limit.

**Attack.** Preconditions: LAN access and the ability to send mDNS responses — nothing more. The attacker announces thousands of `_sonos._tcp` instances with distinct `uuid` values. Alternatively, one adopted rogue speaker returns a topology with a very large `players` array.

**Impact.** Resource exhaustion: one websocket task, one reconnect loop, and one ping timer per phantom player; snapshot recomputation and `localizedStandardCompare` sorting (`SnapshotReducer.swift:26, 29`) over the whole list on every event; the UI list rendering all of them. Degrades to an unresponsive app and sustained CPU/network use. Denial of service only.

**Fix.** Cap the number of tracked players (a real household is well under 32; 64 is a generous limit) and ignore discoveries beyond it. Cap decoded array lengths and string lengths in the wire layer — a custom `init(from:)` on `GroupsResponse` that rejects oversized arrays is the cheapest place. Rate-limit `.found` handling per unit time.

### M-6 — No response-size limit on REST or SOAP bodies

**Files:** `Packages/SonosKit/Sources/SonosKit/Transport/URLSessionTransport.swift:12-15, 26`; `Packages/SonosKit/Sources/SonosKit/UPnP/UPnPClient.swift:101-102`

**What the code does** *(verified)*. `URLSessionConfiguration.ephemeral` is configured with only `timeoutIntervalForRequest = 8` and `httpShouldUsePipelining = false`. `session.data(for:)` buffers the entire response in memory with no ceiling. `UPnPClient.call` then does `String(decoding: response.body, as: UTF8.self)`, materialising a second full copy as a `String`.

Worth noting the contrast: the websocket path *is* bounded, because `URLSessionWebSocketTask.maximumMessageSize` defaults to 1 MiB *(inferred — documented default; not set explicitly here)*. So a huge websocket frame is already rejected. It is the REST and UPnP paths that are open.

**Attack.** Preconditions: a rogue or MITM'd speaker. It answers the topology, favorites, or SOAP request with a multi-gigabyte body. The 8-second request timeout does not help — `timeoutIntervalForRequest` bounds the gap between data arrivals, not the total transfer, so a steady stream keeps it alive indefinitely *(inferred — documented `URLSession` timeout semantics)*.

**Impact.** Memory exhaustion and app termination; on a constrained machine, system-wide pressure. Denial of service only.

**Fix.** Switch the REST and SOAP paths to `session.bytes(for:)` and accumulate with an explicit ceiling (a few MiB is far above any real Sonos response), aborting the task when exceeded. Set `configuration.timeoutIntervalForResource` to bound total transfer time. Set `maximumMessageSize` explicitly on the websocket task rather than relying on the default, so the bound is visible and version-independent.

## LOW

### L-1 — Trust decision is scoped to host only, not host *and* port
`Packages/SonosKit/Sources/SonosKit/Transport/TrustPolicy.swift:30-32`; `URLSessionTransport.swift:63`. *(verified)* `shouldTrust(host:)` ignores `URLProtectionSpace.port`, so once an address is allowed, any certificate is accepted for it on **any** port. Contained in practice — this session only ever dials 1443 and 1400 — but it is a latent widening if the session is ever reused. **Fix:** take `(host, port)` and restrict to `LocalAPIClient.port` / `UPnPClient.port`.

### L-2 — Trust store is never pruned
`TrustPolicy.swift:21-28`; `Household.swift:183-194` (`.lost` handling removes the player but never revokes the host). *(verified)* Entries accumulate for the life of the `URLSessionTransport`. A speaker that leaves the network keeps its address trusted; if DHCP reassigns that address to another device, the app will accept any certificate from it. Reset only happens on `AppState.retryDiscovery()` (`AppState.swift:86`), which builds a fresh transport. **Fix:** revoke in the `.lost` branch, and key the entry to the player UUID (see H-1).

### L-3 — Network identifiers forced to `privacy: .public` in the unified log
`Household.swift:166, 184, 268, 283, 305, 310, 324, 381, 384, 423`; `BonjourDiscovery.swift:41, 65, 70, 75`; `URLSessionTransport.swift:30, 64`. *(verified — 16 sites, all `.public`.)* Private LAN IPv4 addresses, Sonos player UUIDs, and full request URLs are written to the unified log with redaction explicitly disabled. `os.Logger` would redact dynamic strings by default; every site overrides that.

Track metadata is *not* logged — no title, artist, album, or favorite name appears in any log statement, which is the right call and the most sensitive category. Household ids are also absent from request URLs (the API uses the literal `local`, per `knowledge/domain/sonos-local-api.md:3`). So the exposure is topology, not listening history.

**Impact:** log entries persist in the system log store and are captured verbatim in any sysdiagnose the user shares with a vendor. **Fix:** drop `privacy: .public` from IP addresses and player UUIDs (default redaction hashes them consistently, which preserves debuggability), keeping `.public` for enum states and error codes.

### L-4 — `Package.resolved` is not committed; dependency versions float
`.gitignore:5` (`*.xcodeproj`) excludes the whole `SonosRemote.xcodeproj` bundle, which is where SwiftPM writes `project.xcworkspace/xcshareddata/swiftpm/Package.resolved`. *(verified: `git check-ignore -v` confirms the ignore rule matches that path, and `git ls-files` shows no `Package.resolved` tracked.)* `project.yml:11-16` declares both dependencies with `from:`, i.e. up-to-next-major. The resolved file on disk pins `KeyboardShortcuts` 3.0.1 (`49c3fc04…`) and `MenuBarExtraAccess` 1.3.1 (`e93e3a5b…`), but a fresh clone — including a release build via `scripts/release.sh`, which runs `xcodegen generate` at line 85 — resolves whatever is newest in the 3.x / 1.x range. Builds are therefore not reproducible and a compromised or simply changed upstream tag enters a signed, notarized release without review. **Fix:** narrow the ignore to `*.xcodeproj/project.pbxproj` and `*.xcodeproj/xcuserdata`, and commit `Package.resolved`. Add a `git diff --exit-code` check on it in the release preflight.

### L-5 — UPnP EQ traffic is plaintext HTTP
`Packages/SonosKit/Sources/SonosKit/UPnP/UPnPClient.swift:89` (`http://\(address):1400…`), permitted by `NSAllowsLocalNetworking` in `Info.plist:29-33`. *(verified)* This is forced by Sonos — port 1400 offers no TLS — so it is not a design error. Consequence: EQ reads and writes are readable and modifiable by any LAN observer, and the SOAP responses that `UPnPClient` parses are trivially spoofable without needing H-1. Low impact (EQ settings only). **Fix:** none available protocol-side; note it in the README's privacy statement so users on untrusted networks understand the boundary.

### L-6 — Naive substring SOAP parsing can be confused by a hostile response
`Packages/SonosKit/Sources/SonosKit/UPnP/SOAP.swift:29-33`. *(verified)* `value(named:in:)` does `xml.range(of: "<name>")` and takes everything up to the first matching close tag, with no awareness of comments, CDATA, namespaces, or nesting. A crafted response can therefore make the app read a value from a comment or a decoy element. **Impact is genuinely small** — the result is fed to `Int(...)` and used for a bass/treble slider — and the choice to avoid a real XML parser is *positively good* for security (see W-4). **Fix:** optional; if tightened, anchor the search inside the `<s:Body>` range and reject responses containing `<!--` or `<![CDATA[`.

### L-7 — Reconnect attempt counter resets before the connection proves useful
`Packages/SonosKit/Sources/SonosKit/Socket/PlayerSocket.swift:105` (`attempt = 0`), with the backoff at `:127`. *(verified)* The counter is zeroed as soon as `openSocket` returns and the initial subscribes are sent — before any data is received. A host that accepts the TLS handshake and the subscribe frames, then immediately drops, keeps `attempt` pinned at 0, so the delay stays at the ~1 s floor (`Backoff.base`, `Socket/Backoff.swift:9`) forever instead of escalating toward the 60 s cap. Multiply by M-5's phantom players for a sustained connection flood. **Fix:** reset `attempt` only after the connection has been up for a minimum dwell time (say 10 s) or has yielded at least one decoded event.

### L-8 — Release script pushes to whatever repository sits at `$TAP_DIR`
`scripts/release.sh:46, 136-146`. *(verified)* `TAP_DIR` defaults to `$HOME/Sandbox/Code/homebrew-tap` and is environment-overridable. If that path already contains *some other* git repository, the clone at line 138 is skipped (the `.git` check at line 136 passes), and lines 143-146 write `Casks/remote-for-sonos.rb` into it, commit, and `git push -u origin HEAD` — to that repo's origin, which is never compared against `$TAP_REPO`. Operator-local, requires an unusual pre-existing state, no external attacker. **Fix:** after the `.git` check, assert `git -C "$TAP_DIR" remote get-url origin` matches `$TAP_REPO` and `die` otherwise.

## INFORMATIONAL

**I-1 — The API key is a published constant and is correctly not treated as a secret.** `LocalAPI/LocalAPIClient.swift:6` holds `123e4567-e89b-12d3-a456-426655440000` — the RFC 4122 example UUID, documented at `knowledge/domain/sonos-local-api.md:3` and used unchanged by community clients since 2023. It is not logged, not stored, and not user-configurable. Hard-coding it in an MIT-licensed open-source app is the correct call; there is nothing to protect. Disclosing it to an attacker (H-1, H-2) costs nothing.

**I-2 — `git log --all -p` across all 65 commits found no secrets.** The only hits for the secret pattern set were two lines in `knowledge/procedural/release.md` *describing* how to create an app-specific password and store it in the keychain — the credential itself is never in the repo. `scripts/release.sh:44, 67, 105, 109` uses `notarytool --keychain-profile` throughout, so notarization credentials live in the macOS keychain, never in a file or an environment variable. No `.DS_Store` is tracked despite several being present on disk.

**I-3 — `try!` at `Socket/SocketFrame.swift:61` is safe by construction.** `encoder.encode(header)` operates on a `SocketHeader` of `String`/`Bool` optionals that the app itself just built; `JSONEncoder` cannot fail on it. It is the only `try!` in first-party non-test code. Worth converting to `try?` with a `nil` return purely so the file contains no force-try precedent; not a defect.

**I-4 — `MenuBarExtraAccess` reflects into SwiftUI internals.** `MenuBarExtraUtils.swift:267-320` uses `Mirror` to walk `SwiftUI.WindowMenuBarExtraBehavior` and reads `expandedInterfaceDelegate` / `suspendedExpandedInterfaceDelegate` off `NSStatusItem`, with a source comment conceding "this is not ideal, but it's currently the ONLY way". This is not a memory-safety or privilege issue, but it is a brittleness risk across macOS updates (the code already branches on macOS 26 vs 27) and would likely draw App Store review attention were the app ever submitted. Pin the dependency (L-4) so an upstream change cannot land unreviewed.

**I-5 — `KeyboardShortcuts` needs no Accessibility or Input Monitoring permission.** *(verified by grep)* No `CGEvent.tapCreate`, `AXIsProcessTrusted`, `IOHIDRequestAccess`, or `NSEvent.addGlobalMonitor` anywhere in its sources. It registers via Carbon `RegisterEventHotKey` / `InstallEventHandler` (`HotKey.swift:109-110, 263, 305, 383`), which is scoped to the specific registered chord and requires no TCC grant. This is the low-privilege choice and means the app never prompts for — or holds — keyboard-monitoring access.

**I-6 — TLS minimum version is not pinned.** `Transport/URLSessionTransport.swift:12-15` sets no `tlsMinimumSupportedProtocolVersion`. The default is TLS 1.2 *(inferred)*, which is fine today, but for a session that already bypasses certificate validation (H-1) an explicit floor is cheap insurance.

**I-7 — Address-family and range coverage gaps in `TrustPolicy.isPrivateIPv4`.** `TrustPolicy.swift:6-17` covers only 10/8, 172.16/12, and 192.168/16. Not covered: IPv6 (including `fe80::/10` and `fc00::/7`), link-local `169.254/16`, and loopback `127/8`. The failure mode is **fail-closed** — an IPv6-reachable speaker is simply never trusted, so TLS fails and the player is unusable rather than insecurely trusted. That is the right default, but it is a functional gap worth closing deliberately when H-2's shared `isLocalSpeakerAddress` predicate is written. Also note `octets = parts.compactMap { UInt8($0) }` correctly rejects `192.168.1.300` (asserted at `TrustPolicyTests.swift:14`) — good.

## What is done well

- **W-1 — The trust decision fails closed and is deliberately narrow.** `URLSessionTransport.swift:59-66` falls through to `.performDefaultHandling` for non-server-trust challenges and for any host not explicitly allowed, and logs the refusal. `TrustPolicy.swift:31` requires *both* private-range membership and explicit allow-listing. The intent — "self-signed certs only for LAN devices we actually discovered" — is right; H-1 is about the missing pinning underneath it, not the shape of the policy.
- **W-2 — ATS relaxation is minimal.** `Info.plist:29-33` uses `NSAllowsLocalNetworking` alone. There is no `NSAllowsArbitraryLoads`, no `NSExceptionDomains`, no `NSExceptionAllowsInsecureHTTPLoads`. This is the smallest exception that permits the plaintext UPnP port, and it leaves internet-bound loads fully ATS-protected.
- **W-3 — Entitlements are the minimum possible.** `SonosRemote.entitlements` requests exactly `com.apple.security.app-sandbox` and `com.apple.security.network.client` — no `network.server`, no file access, no Apple Events, no camera/microphone, no temporary-exception entitlements. Bonjour browsing is correctly narrowed to a single service type via `NSBonjourServices` (`Info.plist:34-37`) with a truthful `NSLocalNetworkUsageDescription`.
- **W-4 — No XML parser is used at all.** *(verified by grep: zero hits for `XMLParser`, `XMLDocument`, `shouldResolveExternalEntities`, `NSXML`.)* `UPnP/SOAP.swift` does bounded string-range extraction instead. This eliminates XXE, billion-laughs entity expansion, and external-DTD fetches as a class — exactly the right trade for parsing two integers out of a fixed response shape. The outbound direction escapes all five XML entities (`SOAP.swift:13-26`).
- **W-5 — Websocket frame decoding is failure-tolerant by design.** `PlayerSocket.swift:115` wraps `SocketFrameDecoder.decode` in `try?`, so a malformed or hostile frame is dropped and the loop continues. `SocketFrameDecoder` (`SocketFrame.swift:81-123`) decodes the header first and dispatches on `type`, with `default:` returning `.unknown` rather than throwing. `PlaybackState.init(wireValue:)` (`Models/Models.swift:10-12`) maps unknown firmware values to `.idle` with an explicit comment about never crashing. `Favorite.Kind.init(resourceType:)` (`Models.swift:112-119`) does the same. This is consistently good defensive decoding — H-4 is the one place a decoded value escapes unclamped.
- **W-6 — Errors shown to the user are fixed strings.** `AppState.message(for:)` (`AppState.swift:238-253`) maps every error case to a hard-coded sentence; no raw error, URL, IP, or server-supplied text reaches the UI. Contrast with the many apps that render `error.localizedDescription` straight from the network layer.
- **W-7 — The only URL the app ever opens is a compile-time constant.** `SettingsScreen.swift:11, 64` — `Link(destination:)` with a hard-coded GitHub releases URL. No `NSWorkspace.open`, no `openURL` on wire data anywhere *(verified by grep)*.
- **W-8 — Version input to the release script is strictly validated before any use.** `scripts/release.sh:19` gates on `^[0-9]+\.[0-9]+\.[0-9]+$` and calls `usage` otherwise, so `$VERSION` is safe in the `sed` substitution at line 143, the tag name, and the paths. `set -euo pipefail` is set (line 14). Release notes reach `gh` via `--notes-file` (line 132), never as an interpolated argument. Notarization cannot be skipped on a published build — line 126 exits before `gh release create` if either `--skip-notarize` or `--skip-publish` was passed. The preflight refuses a dirty tree (line 57), an existing tag (line 61), an unauthenticated `gh` (line 62), a missing changelog section (line 64), and a missing signing identity (line 65).
- **W-9 — Release builds get the hardened runtime; `LSUIElement` keeps the app out of the Dock.** `project.yml:36-37` sets `ENABLE_HARDENED_RUNTIME: YES` with a Developer ID identity for Release, and the script verifies with `codesign --verify --strict`, `stapler validate`, and `spctl -a -t exec` (lines 98, 114-115). Hardened runtime is off only for Debug (line 33), with an accurate comment explaining the test-host injection requirement.
- **W-10 — Concurrency hygiene is strong.** `SWIFT_STRICT_CONCURRENCY: complete` and Swift 6 language mode (`project.yml:19-20`, `Package.swift:20`). State is owned by an `actor` (`Household`), `Mutex` from `Synchronization` guards the trust store and browser session, and continuations are finished on every teardown path with comments explaining the races (`BonjourDiscovery.swift:50-57, 85-91`; `Household.swift:286-288`). Race-condition bug classes are largely designed out.

## Prioritised top 5

1. **H-1 — Pin the certificate.** Record the leaf SPKI hash on first contact, require a match thereafter, persist it across launches, and surface a mismatch in the UI. This is the single change that most reduces blast radius: it closes LAN impersonation and simultaneously demotes M-1 from "attacker widens accept-any-cert" to "attacker names hosts that still have to prove identity". `Transport/URLSessionTransport.swift:63-68`, `Transport/TrustPolicy.swift:20-33`.
2. **H-2 — Validate discovered addresses before storing or dialling them.** One shared `isLocalSpeakerAddress` predicate — scheme allowlist, IP literal required, private/link-local range required — applied in both `BonjourDiscovery.player(fromTXT:)` and `WirePlayer.host(fromWebsocketURL:)`. This stops the app from ever contacting the internet on a Bonjour trigger, and removes most of H-3's crash input space as a side effect. `Discovery/BonjourDiscovery.swift:26-31`, `Wire/WireTypes.swift:30-32`.
3. **H-3 — Remove the three `preconditionFailure` calls on network-derived URLs.** Make them recoverable errors that the existing `catch` paths already handle. A mDNS packet from anyone on the LAN should never be able to abort the process. `LocalAPI/LocalAPIClient.swift:87-89`, `Socket/PlayerSocket.swift:31-33`, `UPnP/UPnPClient.swift:89-91`.
4. **H-4 — Clamp `positionMillis` and `durationMillis` at the wire boundary** and make the two progress-bar arithmetic sites overflow-safe, with a regression test at `Int.max`. `Wire/WireMapping.swift:46-56`, `Socket/SocketFrame.swift:98`, `App/PlaybackDisplay.swift:11, 24`.
5. **M-3 + M-4 + L-4 — Close the content-trust gaps.** Restrict artwork URLs to `https` or private-host `http` (`Wire/WireMapping.swift:24, 37`); change `GroupScreen.swift:62` to `Text(verbatim:)` so a track title cannot become a clickable link; and commit `Package.resolved` by narrowing `.gitignore:5`, so the dependencies inside a signed, notarized release are the ones that were reviewed.
